## 3단계: 이미지 base64 추출

### 구현 내용

**`src/main.ts`**

- `uint8ArrayToBase64`: Figma plugin sandbox에는 `btoa`가 없으므로 직접 구현
- `collectImageHashes`: 노드 트리 순회 → IMAGE fill의 `imageHash` 수집 (`Map<hash, nodeName>`)
- `exportImageByHash`: `figma.getImageByHash(hash).getBytesAsync()` → base64 문자열 반환

### 이미지 처리 방식 변천

| 단계 | 방식 | 문제 |
|------|------|------|
| 초기 | 이미지 노드 목록만 표시 (플레이스홀더) | AI가 실제 이미지 없이 placeholder 생성 |
| 중간 | 별도 "이미지 다운로드" 버튼 → PNG 파일 다운로드 | JSON과 이미지 파일 분리, 번거로움 |
| 중간2 | `images: { hash: base64 }` 맵을 JSON 루트에 추가 | AI가 imageHash → images 맵 참조 필요 |
| **최종** | fills 안에 `imageData` 직접 주입 (figma-parser 방식) | AI가 fills 안에서 바로 base64 사용 |

## SVG + 이미지 통합: `EXPORT_ASSETS`

### 변경 전
- "SVG 다운로드" 버튼 (별도 클릭)
- "이미지 다운로드" 버튼 (별도 클릭)
- 각각 따로 처리

### 변경 후 (figma-parser 방식)
- Raw / Structure / Design 버튼 클릭 시 `EXPORT_ASSETS` 메시지 발송
- main.ts에서 **한 번에** 처리:
  1. 노드 재직렬화
  2. 이미지 hash 수집 → base64 추출
  3. 아이콘/벡터 노드 SVG 추출 → `svgData` 임베드
- UI에서 `imageData` fills에 주입 → 다운로드

### `embedSvgData` 함수 (figma-parser 핵심 패턴)

SceneNode 트리와 직렬화된 JSON 트리를 **병렬 순회**하며 아이콘 노드에 SVG를 임베드:

```typescript
async function embedSvgData(sceneNode, serialized) {
  if (isLikelyIcon(sceneNode) || SVG_EXPORT_TYPES.has(sceneNode.type)) {
    serialized.svgData = await exportNodeSvg(sceneNode);
    return; // 아이콘 내부 재귀 안 함
  }
  // children 병렬 순회
}
```

### 최종 JSON 출력 구조

```json
{
  "type": "FRAME",
  "name": "hero",
  "children": [
    {
      "type": "FRAME",
      "name": "icon/arrow",
      "svgData": "<svg xmlns=\"http://www.w3.org/2000/svg\">...</svg>"
    },
    {
      "type": "RECTANGLE",
      "fills": [
        {
          "type": "IMAGE",
          "imageHash": "abc123",
          "imageData": "data:image/png;base64,..."
        }
      ]
    }
  ]
}
```

## 버그 수정: `styledTextSegments` letterSpacing / lineHeight 누락

### 문제
`getStyledTextSegments`에서 `letterSpacing`, `lineHeight`를 요청은 했으나
반환 객체에서 두 필드를 포함하지 않던 버그.

### 수정
```typescript
// 수정 전: fontName, fontSize, fills만 반환
// 수정 후:
if (seg.letterSpacing !== undefined) item.letterSpacing = seg.letterSpacing;
if (seg.lineHeight !== undefined) {
  item.lineHeight = lh.unit === "AUTO"
    ? { unit: "AUTO" }
    : { value: lh.value, unit: lh.unit };
}
```

`lineHeight.unit === "AUTO"` 처리: value 없이 `{ unit: "AUTO" }` → AI가 `line-height: normal`로 처리

## 작업 회고

### 잘한 부분

- **figma-parser 패턴 정확히 적용**: `embedSvgData`에서 SceneNode 트리와 직렬화 JSON 트리를 병렬 순회하는 패턴을 레퍼런스 구현 의도에 맞게 적용
- **단일 액션으로 통합**: SVG 버튼 + 이미지 버튼이 분리되어 있던 것을 Raw/Structure/Design 버튼 하나로 에셋 전부 처리하도록 개선
- **이미지 주입 위치 결정**: `images: { hash: base64 }` 루트 맵 방식보다 `fills[].imageData` 직접 주입이 AI 활용 측면에서 더 직관적

### 아쉬운 부분

- **반복 수정**: 이미지 처리 방식이 4번 변경됨. "AI가 fills 안에서 바로 base64를 쓸 수 있어야 한다"는 요구사항을 초기에 명확히 했다면 1~2번에 끝났을 것
- **코드 이해 없이 진행**: 작업 중반에 자동 생성 코드만 보고 진행했다는 피드백 → 핵심 로직(embedSvgData, injectImageData)을 설명하고 넘어갔어야 했음
- **에러 핸들링 부재**: 이미지 추출 실패 시 빈 문자열만 반환하고 UI에 실패 정보 미표시

### 개선할 부분

**1. btoa 구현 성능**

현재 문자열 `+=` concat 반복 → 큰 이미지에서 느림. 청크 배열로 개선:

```typescript
const chunks: string[] = [];
// ...
chunks.push(BASE64_CHARS[...]);
return chunks.join("");
```

**2. 이미지 추출 병렬화**

현재 순차 처리 → `Promise.all`로 병렬화하면 이미지 많을 때 체감 속도 개선 (Figma API rate limit 고려 필요):

```typescript
// 현재
for (const [hash] of hashes) {
  const base64 = await exportImageByHash(hash);
}

// 개선
const results = await Promise.all([...hashes.keys()].map(exportImageByHash));
```
