## figma-extract 스킬

### 배경

기존 플러그인 방식은 Figma에서 manifest.json으로 직접 설치해야 해서 팀 배포 허들이 높았음.
Figma REST API를 사용하면 플러그인 설치 없이 URL + 토큰만으로 동일한 JSON을 추출할 수 있다는 점에서 스킬로 제작.

### 구현 내용

**`skill/scripts/figma_extract.py`**

- Figma URL에서 `fileKey` + `nodeId` 자동 파싱 (node-id의 `-` → `:` 변환 포함)
- `GET /v1/files/:fileKey/nodes?ids=:nodeId` 호출
- `App.tsx`의 `STRUCTURE_KEYS` / `DESIGN_KEYS` / `QA_KEYS` 필터링 로직을 Python으로 재현
- IMAGE fill → `imageSlot` 메타 객체 변환 (`transformImageFill` 동일 로직)
- `{frameName}_structure.json`, `{frameName}_design.json`, `{frameName}_qa.json` 로컬 저장

### 사용법

```bash
export FIGMA_TOKEN=figd_xxxx

python3 skill/scripts/figma_extract.py \
  --url "https://www.figma.com/design/ABC123/...?node-id=1-23" \
  --output ./output
```

### 플러그인 대비 제약

| 항목 | 플러그인 | 스킬 |
|------|---------|------|
| 설치 | manifest import 필요 | 없음 (토큰만) |
| 프레임 선택 | Figma에서 클릭 | URL 직접 전달 |
| styledTextSegments | 지원 | 미지원 (Plugin API 전용) |
| 이미지 | base64 직접 추출 | imageSlot 메타로 대체 |

### Figma MCP 대신 REST API를 선택한 이유

Figma MCP로도 동일한 스킬 제작이 기술적으로 가능하나, 선택하지 않은 이유:

- **Rate limit(429)**: 플러그인 대신 REST API를 도입한 근본 원인이 Figma MCP의 429 Too Many Requests 문제였음. 스킬도 MCP를 호출하는 구조라 동일한 문제가 재발함
- **의존성**: MCP 서버가 설치·실행 중이어야 동작 → 환경 의존성 증가
- **단발성 호출**: REST API 스킬은 요청당 2-3번 API 호출로 끝나 Rate limit 위험 없음

### 배포 방법

저장소를 클론한 뒤 심볼릭 링크로 설치:

```bash
ln -s $(pwd)/skill ~/.claude/skills/figma-extract
```

전역에도 동일하게 `~/.claude/skills/figma-extract/`에 별도 복사본 유지 중.
